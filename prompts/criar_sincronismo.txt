OBJETIVO
Para cada beat_id, devolva de zero a três event_id candidatos, ordenados do melhor para o pior.

CRITÉRIOS
- Se a fala menciona uma ação concreta (ex.: "tiro da tomada"), priorize um evento que MOSTRA essa ação, não um b-roll do produto.
- Se a fala menciona um fenômeno (ex.: "faixa escura", "pisca", "flicker"), selecione somente evento em que o fenômeno esteja explicitamente catalogado como visível.
- Respeite a escrita espelhada na imagem e o phonetic_budget: a frase deve sincronizar com precisão sub-segundo no ápice visual (visual_anchor).
- Se a fala é contextual/genérica, b-roll relevante é permitido.
- A ordem temporal e causal importa. "Antes", "quando", "depois", "passa para bateria", "volta para rede" não são equivalentes.
- Não use uma cena só porque contém o mesmo produto; ela precisa sustentar o que está sendo dito naquele instante.
- Para beats críticos, seja conservador. Se não houver evidência suficiente, retorne candidates=[] em vez de adivinhar.
- score deve representar a confiança semântica real do casamento.
- required_observation deve descrever objetivamente o que PRECISA estar visível para a cena estar correta.
- critical=true quando um erro visual seria percebido pelo espectador: ação física, mudança de estado, comparação, fenômeno visual, resultado de teste ou demonstração.

CRONOLOGIA
- Cada evidência possui sequence_index. Se chronology_mode="strict", eventos críticos devem respeitar progressão cronológica, exceto quando a própria fala indicar retorno/flashback/repetição.
- Se chronology_mode="guided", use a ordem como forte preferência, mas um b-roll contextual pode vir de outra posição quando não contradiz causa/estado.
- Para uma cadeia "ação -> mudança de estado -> resultado", preserve essa ordem na imagem.
- Se um candidato violar um fato bloqueado ou exibir estado causalmente incompatível, não o selecione.
